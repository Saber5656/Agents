# モバイルアプリのテスト環境

モバイルアプリの実装・UI改善・動作確認・引き渡しに適用する。普段の修正と確認はエージェントが利用可能な Simulator / Emulator で進め、実機が必要な確認を具体化して利用者へ依頼する。実機待ちでも、独立して進められる修正や検証は継続する。

## 環境の役割

| 環境 | 主な確認内容 | 結果の扱い |
|---|---|---|
| Webプレビュー | 大まかな構成、Web向け表示、入力ロジック | ネイティブUIや実機起動の証拠にはしない |
| iOS Simulator / Android Emulator | ネイティブ画面、端末サイズ、文字拡大、キーボード、画面遷移、入力エラー | 確認した仮想端末・OS・操作の範囲で記録する |
| 物理端末 | 指での操作感、実センサー、通知音・振動、ロック中・バックグラウンドの挙動、実際の性能 | 実機で観測した結果として記録する |
| 配布用ビルドを入れた物理端末 | 利用者へ渡す構成での主要操作、権限、通知、復帰、必要な更新経路 | リリース前の受け入れ確認とする |

SimulatorはMac上で仮想のiPhoneを動かす環境であり、手元のiPhoneの画面共有とは異なる。ネイティブのLiquid Glassや標準ピッカーの表示を確認できても、実機の描画性能、触覚、指で操作した感触まで確認済みとはしない。

CLIハーネス自体がGUI操作機能を提供するわけではない。実行先で利用可能な専用ツール・CLI・GUI操作ツールと権限を確認する。仮想端末が起動できることと、エージェントが画面を見て主要操作を実行できることを区別する。スワイプなどが操作ツールで再現できない場合、その操作だけを未確認として残し、コードからの推測で埋めない。

## 実機確認を挟む時点

- リリース直前だけにまとめない。センサー、通知、権限、バックグラウンド処理、ネイティブ依存やSDKなど、実機固有の挙動に影響する変更の節目でも確認する。
- 例えば歩数でアラームを止めるアプリでは、スマホを持って歩いたときの検知、停止対象、通知音、画面ロックやアプリの復帰を実機で確認する。仮想の歩数や通知イベントはロジック検証に使えても、実センサーや実際の通知経路の確認を代替しない。
- Expo Goでの起動と、アプリ固有のdevelopment build、配布用のrelease buildでの起動は別の結果として扱う。最終確認には実際に配布するビルドを使う。バックグラウンド確認はデバッガ接続に依存せず、ホーム画面から起動して行う。
- この方針はSDK更新、配布方式の変更、署名・アカウント設定、ストア申請、追加費用を一括で許可するものではない。今回の依頼で許可された範囲を引き継ぐ。

## iPhoneミラーリング

iPhoneミラーリングは、物理iPhoneの画面をMacから見たり操作したりする任意の補助機能とする。Simulatorでの開発や、利用者がiPhoneを直接操作する実機テストの必須条件にはしない。ミラーリングを使うためだけに普段の開発を止めない。

ミラーリング経由のマウス・キーボード操作と、iPhoneを手で操作した確認は区別する。利用可能な機能・制約はAppleの現行案内と実際の環境で確かめ、Codexからの自動操作が可能だと未確認のまま約束しない。

## 記録と利用者への引き渡し

1. 作業ディレクトリとcommit（未コミット差分があればその状態）、OS、端末名・画面サイズ、文字サイズ、実機/仮想端末、ビルド種別を記録する。Expo Goを使う場合はクライアント・プロジェクト依存・配信manifestのSDK整合も確認する。
2. 実行した操作、期待結果、観測結果、スクリーンショット・ログ、未確認項目を対応付ける。build/export/CI成功、仮想端末起動、主要操作成功、実機確認、配布用ビルド確認を分けて報告する。
3. 実機操作を依頼するときは、目的、本人の操作が必要な理由、対象端末とビルド、操作手順、期待する結果、返してほしい情報を用意する。既にある画像や端末情報は聞き直さない。
4. 確認できない事項と再開条件をVaultに残す。インストール済みの環境や過去の成功だけを根拠に「実機確認済み」「リリース可能」としない。
