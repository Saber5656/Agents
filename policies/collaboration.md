# 作業と役割の協働

- 利用者の目的と完了条件を共有し、必要な専門性を組み合わせて成果へ進める。
- ロールは責務と品質観点の参照であり、主担当が複数の役割を兼ねてもよい。人数、担当順序、階層、利用モデルは作業に合わせて判断する。
- 依存する作業は前提を共有し、独立した作業は有益な場合に並行して進める。共通ルールの委譲方針に従う。
- 判断・実装・テスト・品質確認・文書化を必要に応じて組み合わせ、成果間の矛盾を解消する。
- 全変更をレビューし、対象・担当・方法・指摘・対応を残す。専門知識が必要な論点は、その知識を使って確認する。
- 実装の振る舞いは TDD で確認し、文書や設定には適した検証を行う。
- 利用者が決める要件は、選択肢・影響・推奨とともに示す。それ以外は目的の範囲で自律的に進める。
- 計画したモデルや担当と、実際に使ったモデルや担当を区別し、取得できた使用量や実行結果を残す。
- 作業と判断の全コンテキストは Vault に保存し、担当間には必要な情報と原記録への参照を渡す。
