# Zenn / Qiita 差分メモ

必要なときだけ読む。記事の中身を考える段階ではなく、出力をプラットフォーム向けに整える段階で参照する。

## 共通で意識すること

- タイトルは具体的で簡潔にする
- 環境や前提条件を書く
- 引用元や参考元のリンクを付ける
- 読者が何を得られるかを冒頭で分かるようにする

この方針は、Qiita の記事ガイドラインと、Zenn/Qiita 上の読みやすい記事例に沿う。

## Zenn

### 向いている記事

- 再現手順つきの技術記事
- 検証メモ
- 運用知見
- Idea 記事

### frontmatter

```yaml
---
title: "記事タイトル"
emoji: "📝"
type: "tech"
topics: ["zenn", "writing"]
published: false
---
```

必要に応じて `published_at` を追加できる。

### 本文で意識すること

- body の見出しは `##` から始める
- 補足や注意喚起には `:::message` / `:::message alert` が使える
- 長い補足は `:::details` に逃がせる
- コードブロックは必要なら `ts:file.ts` のようにファイル名を付ける
- 画像には必要なら alt とキャプションを付ける

### 記事種別

- `tech`: 実装、検証、手順、具体的な技術知見
- `idea`: 意見、整理、学び、考え方

## Qiita

### 向いている記事

- ハマりどころ共有
- 実務で使った知見のメモ
- 比較的ライトな技術メモ

### frontmatter

```yaml
---
title: 記事タイトル
tags:
  - "TypeScript"
  - "Next.js"
private: false
slide: false
---
```

公開後に `id` などが入ることがあるが、下書き時点では最低限でよい。

### 本文で意識すること

- GFM ベースで素直に組む
- タグは 1〜5 個に収める
- 限定共有やスライドモードの有無を意識する
- 補足は `:::note` 系や通常の引用でも表現できる

## 実装前の判断

次の条件でプラットフォームを決める。

- Zenn を普段使っていて、frontmatter 付きの Markdown を扱いたいなら Zenn
- Qiita のタグ流通や限定共有を活かしたいなら Qiita
- どちらでもよいなら、ユーザーの既存運用に合わせる

## 最後の整形で確認すること

- title / tags / topics は本文と一致しているか
- 読者向けの約束と見出し構成がズレていないか
- プラットフォーム固有の記法を多用しすぎていないか
