# Prepare 3D Print

用途に合った入口から始め、実行した工程と確認できた性質だけを報告する。
特定の生成サービス・プリンター・キャラクターに固定しない。

## 1. 既存情報と到達点を確認する

環境の共通指示に従って `AGENTS_ROOT`、`SKILLS_ROOT`、`AGENTS_VAULT_ROOT` を解決する。
未設定なら信頼済み `~/.config/agents/environment.env` から既存の正本 `.env` を確認し、
必要なプロセスへ明示的に読み込む。新しいVaultを推測して作らない。

まず既存Vault内の次の記録を読む。所在変更時は既存Vault内で検索する。

1. `03-Contexts/3d-printing.md` と対象案件の最新記録。
2. `01-Projects/3d-printing/プリンター環境.md`、`材料選定ルール.md`。
3. 同プロジェクトの `材料/*.md` の現在のプロパティと、関連する予約・使用履歴。

所有申告、実際の装着状態、メーカー仕様を区別する。台帳で分かる機種・手持ち材料を
再質問せず、確認日と未確認点を引き継ぐ。台帳が読めなければ参照不能を記録し、
現在の依頼で分かる条件から独立作業を進める。
機種名や「Combo」からAMS現物構成、ノズル径、乾燥状態を補完しない。
購入検討品を所有扱いにせず、在庫残量・予約や既存造形データを依頼なく変更しない。

用途、完成寸法と単位、材料、求める性質（色、柔軟性、荷重、はめ合い等）、
入力原本、今回の到達点を整理する。情報不足は依存する工程だけを保留する。
写真に写る物や既存の仮モデルの寸法を、利用者が指定した実寸と扱わない。

## 2. 入口を選ぶ

| 入力・目的 | 進め方 |
|---|---|
| キャラクター、装飾、自由曲面の原型が必要 | 基準画像 → 整合した正面・側面・背面 → Tripo **または** Hi3D等 → Blenderで印刷用整形 |
| 寸法・固定・はめ合いを要するケース、治具、接続部 | 実測値と公差を管理できるCADを主体にする。装飾外形が必要な場合だけ生成メッシュと組み合わせる |
| 既存のSTL/OBJ/GLB/FBX/.blend等がある | 原本の複製と現状検査から始める。理由なく画像生成やTripoへ戻さない |

画像から新しい原型を作る計画では、三面図の整合確認、原型生成、印刷用構造設計を
別の工程として示す。生成ツールが今使えなくても計画から原型生成を落とさず `NOT_RUN` にする。
手作業のモデリングやCADで外形を作る方が適する場合は、その代替経路と選んだ理由を示す。

画像経路では基準画像・向き・色・部位配置を共有し、同じポーズ、体格、縮尺の
正面/側面/背面を揃える。輪郭と部位位置を照合し、食い違いを修正してから生成へ進む。
見えない背面等は「デザイン案」であり、元画像から判明した事実ではない。
画像生成が必要なら利用可能な画像用スキル/ツールを併用し、未生成を生成済みとしない。

生成サービス利用時は [references/services-and-formats.md](references/services-and-formats.md) を読む。
現行プラン、費用、出力形式、アップロード先、公開範囲、商用利用条件を公式資料で確認する。
スキルの作成・導入依頼は、契約、有料生成、モデルや画像の外部アップロード、実機印刷の許可ではない。
実際の依頼で既に許可された範囲は引き継ぎ、不足する操作の直前だけ確認する。
資料が取得できない場合は未確認の機能・プランを断定せず、ローカル経路を続ける。

## 3. 印刷用に整形する

Blenderを使う工程では [references/mesh-and-prototype.md](references/mesh-and-prototype.md) を読む。
原本を保持し、編集用 `.blend` を別名保存する。CAD経路はCAD原本・パラメータも保持する。
GUIは外観と比較に、Python/API/CLIは再現できる寸法・メッシュ処理に使い分ける。
参照記事の「必ずComputer Use」を工程制約として継承しない。
Blenderがない場合は実行済みの修復や `.blend` を捏造せず、利用可能な検査と作業仕様を残す。

- 無地表示でテクスチャ依存の見かけと実形状を区別し、指の本数、顔や輪郭の破綻を確認する。
- 穴、非多様体、法線、自己交差、浮遊部品、薄肉、接合、実寸を検査する。
- 分割、位置合わせ、組付け公差、接地、積層方向、支持とサポート除去性を検討する。
- 自動修復後は外形・必要な穴・部位数・寸法を前後比較する。閉じたメッシュだけで合格にしない。
- ポリゴン数を品質条件にしない。200万ポリゴンより、出力寸法で残す輪郭・凹凸を基準にする。

ボーン/リギングはポーズ変更が必要なときだけ使う。固定ポーズでは不要で、
可動玩具の物理関節・クリアランスとは別設計。ポーズを決めた印刷用複製へ変形を確定し、
書き出した実形状を確認する。Webビューアは任意で、メッシュ検査や層プレビューの代用にはしない。

## 4. 書き出し、スライス、試作

STLまたは対応を確認した3MF等へ書き出し、再読み込みで寸法・向き・部品を照合する。
STLに画像テクスチャは残らない。3MFの色/テクスチャ格納、受け手の対応、
実機の色割当は別に確認する。3MF拡張子だけでカラー造形を保証しない。

実機に対応するスライサーとプロファイルを選び、実機、ノズル、材料、供給経路、
プレートを確認してから最終設定を決める。未知の数値で最終G-codeを確定しない。
汎用プロファイルでの検討なら「仮スライス」と明記する。
層プレビューで消えた細部、薄壁、内部の空洞・ダクト、宙に始まる層、接地、支持と
除去経路を確認する。材料ごとの本体・サポート・パージ等の見積りと実使用を区別する。

TPUで「潰れて戻る」要求では、外形と弾性構造を別工程にする。
中空構造、壁厚、空気の逃げ、接合部を設計し、実寸の試作で押し込み量・力・復元時間・
残留変形を確認する。硬度の異なる尺度を数値だけで比べない。
材料名だけで復元性を達成扱いにせず、ノズルや材料未確定のまま万能の壁厚・温度を決めない。
はめ合いは接続部の試験片から、弾性は最終サイズの機能部から検証する。

## 5. 証拠を残して渡す

[assets/job-record.md](assets/job-record.md) を作業記録にコピーし、該当部分を埋める。
原本、編集データ、印刷用データ、修正前後画像、メッシュ検査、スライス結果、試作結果を分け、
関連ファイル・バージョン・寸法単位・実機設定を対応付ける。

各工程は `PASS`（観測した基準を満たす）、`FAIL`（観測した不合格）、
`NOT_RUN`（未実行）を使い、根拠・制限を添える。
任意工程を省いた場合も `NOT_RUN` と理由を残す。実行できた一部の検査で工程全体をPASSにしない。
原本保持やファイル作成のPASSには、実ファイルの存在と保持/書出し結果の読取確認が必要。
文章上の入力一覧、予定、fixtureの宣言だけでは実ファイルを保持したことにならない。
合成fixtureの結果を実モデル/実機の結果へ流用しない。
生成だけで「印刷可能」、スライスだけで「造形成功」と言わない。
最終回答は作成物、確認済みの範囲、未実行工程、次に必要な測定や試作を示し、Vault記録へリンクする。

## 使用例

- 「このキャラクター画像を、押し潰して戻る手のひらサイズの造形にしたい」
- 「このGLBを固定ポーズの印刷用に直して。原本は残して」
- 「人形の口と掃除機をつなぐ部品を作りたい。測る位置から整理して」

## 実行環境

読み取り・計画はモデル/有料サービス/プリンターなしでも可能。
編集はBlenderまたは用途に合うCAD、層確認は対応スライサーが必要。
ローカル処理は許可された作業領域で行う。ネットワークは公式資料確認や許可済みの外部工程に限り、
サービス契約・GUI・拡張機能・実機への接続を導入済みと仮定しない。
